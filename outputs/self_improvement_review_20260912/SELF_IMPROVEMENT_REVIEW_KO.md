**LoCoMo 자기개선 전체 이력과 LongMemEval 일반화 검토**

작성일: 2026-09-12. 보존된 로컬 소스·점수 감사·실험 보고서를 읽어 정리했다. 새 GPU 실험이나 서버 상태 변경은 수행하지 않았다.

**먼저 결론**

기억하신 수십 회 개발은 실제로 있었다. 최초 18개 이력 장부의 215행에서 복사된 이력을 제거하면 129개 평가 구성이 남는다. 시작 기준 1개와 재현 확인 2개를 제외하면 **후보·대조군 설정 126개**, 당시 개발 평가에서 개선으로 채택된 것은 **7개**다. r40는 선택된 중간 결과이며, 가장 큰 번호는 r68이다. 126은 독립 아이디어나 성공 횟수, GPU 실행 횟수를 뜻하지 않는다. 내부 source 재귀 결정은 중복 계산하지 않았다. [집계 근거](../../generalization_20260908/modern/REFINEMENT_HISTORY_COUNT.md)

이 개발 점수는 **Qwen3-8B + Qwen3-Embedding-0.6B, LoCoMo 동일 개발 70문항의 공식 방식 F1×100**이다. 원래 요청 모델 Qwen3.5-9B 대신 8B로 실행한 오류가 기록되어 있어, 이 점수를 9B 성능으로 바꿔 부르면 안 된다. 후속 모델·임베딩·문항 집단이 다른 점수는 아래에서 별도로 제시한다. 반복 선택에 사용한 dev70의 상승은 일반화 증명이 아니다. [모델 구분](../../generalization_20260908/README.md)

**자기개선이 실제로 작동한 방식**

외부에서 작성해 큐에 추가한 일반적인 메모리 변환 후보를 기존 최고 메모리에 적용하고, 고정된 개발 질문으로 평가한 뒤 F1이 개선되면 최고 후보를 교체했다. 워커 자체가 새 소스 코드를 작성하거나 새 recipe를 발명하는 부분은 없다. 원문을 메모리로 만드는 함수에는 benchmark QA/gold를 넘기지 않았지만, 바깥 개발 루프의 선택은 동일 dev70 점수를 반복 사용했다. `연속 실행 코드` (historical source: `generalization_20260908/source/continuous_v3.py:260`)

후기의 t/v 계열과 별도 Recursive v1에는 원문에서 생성한 질문의 검색·응답 실패를 다음 메모리 수정에 직접 반영하는 내부 루프도 있다. y/z 계열은 저장 검색벡터를 조절하며 LLM·인코더 가중치는 학습하지 않는다.

**전체 방법을 이해하는 용어**

- 검색키는 메모리를 찾는 텍스트이고, 본문(payload)은 최종 답변 모델이 읽는 근거다. 여러 실험은 둘을 분리했다.
- source 질문은 원문 대화에서 만든 자체 점검 질문이다. benchmark 평가 질문과 구별한다.
- single 계열의 후보군은 단일 근거와 전체 근거, joint는 여기에 근거 쌍까지 포함한다. single이 언제나 한 발화만 읽는다는 뜻은 아니다.
- verified는 같은 모델이 후보 답이 원문 답의 의미·인물·사건·시간·수량·조건을 유지하는지 비교하는 절차다. 독립적인 정확성 보증은 아니다.
- 2,000/4,000은 추가 저장 토큰 상한이며 검색키와 본문 비용을 함께 센다. 읽기 예산은 대체로 2,048토큰이고 ad 계열은 이를 줄이는 실험이다.
- 장부의 accepted는 당시 채택 표시다. 특히 후기 후보는 source 질문에서 선택을 먼저 고정하기도 하므로, dev 최고 점수와 source 선택을 같은 것으로 해석하지 않는다.

**시도한 방법 전체: 계열별 설명**

1. **초기 추출(r00–r04):** 세션별 제한된 사실 추출, 사건 중심 재추출, 누락 사실 감사, 원문 대화 보강, 출처 인용 결합을 비교했다. 사건 재추출 37.3707, 출처 인용 45.1160은 미채택이고, 누락 보강과 원문 대화 추가가 채택됐다. `구현` (historical source: `generalization_20260908/source/refine.py:319`)
2. **날짜 처리:** 상대 날짜를 기록일에 연결하고, 월 단위 해석 또는 시간 표현이 있는 단위만 처리했다. r06 54.8601이 당시 채택됐고, 이후 선택적 날짜 처리 최고 r36 56.7412는 당시 최고를 넘지 못했다.
3. **원문 블록 구성:** 1/2/3/4턴, 중첩·비중첩, 날짜 처리·필터 조합, 사실만/대화만 보존을 시험했다. 해당 비교 15개의 범위 47.9503–56.0483. 가장 높은 것은 r20(날짜 처리+3턴) 56.0483.
4. **사교 표현 필터:** 감사·격려·축하 같은 상투적인 사실을 제거했다. r11 단독 조합 51.7203, 당시 최고에 적용한 r12 57.1189. 효과는 적용 부모와 조합에 따라 달랐다.
5. **사실/QA 카드:** 추출형 카드, 서술형 사실, 원문에서 만든 질문·답 카드, 날짜 적용, 원문 문맥 추가, 중복·질문·빈 표현 정리를 비교했다. 13개 범위 40.3402–55.3955. 가장 높은 r44도 당시 최고를 넘지 못했다.
6. **사실+원문 결합:** 출처가 겹치는 원문 블록에 추출 사실을 붙여 하나의 검색·읽기 단위로 만들었다. 2턴 55.9514, 3턴 53.2420, **4턴 r40 58.6203**, 5턴 56.3245, 6턴 52.9560, stride1 54.3112, 별도 사실 인덱스 추가 53.7733. `구현` (historical source: `generalization_20260908/source/memory_ops.py:48`)
7. **인물 프로필:** 인물×주제로 여러 세션의 관계·취미·직업 등의 사실을 통합했다. 프로필 추가 54.5054, 프로필만 7.8390, 문맥 조합 47.5157. 프로필만 보존한 구성은 크게 나빠졌다.
8. **중요 발화 선택:** LLM이 정보 없는 인사·감사 등을 골라 제외하고, 의미 있는 발화와 앞 문맥을 보존했다. 58.1404, 발화만 45.4402, 긴 문맥 57.3990. 모두 r40 미만. `프로필·발화 선택` (historical source: `generalization_20260908/source/memory_ops.py:90`)
9. **검색키/본문 분리와 규칙 제거:** 사실은 검색에, 원문은 답변 근거에 쓰는 구성; 본문에 사실 요약도 유지하는 구성; 원문 잔여 항목 제외; 날짜·필터 규칙을 추가하지 않는 m01–m04 대조를 시험했다. 10개 범위 45.8590–54.3912. 검색키 분리가 자동으로 유리하지 않았다. `구현` (historical source: `generalization_20260908/source/indexed_memory.py:37`)
10. **b: 근거 예산 배분:** 원문에서 만든 질문의 답 토큰 가능도를 빈 문맥/단일/쌍/전체 근거에서 비교해 유용한 근거를 선택했다. 저장 상한을 원문 1.25배/1.5배로 두고 배낭 최적화했다. 원문 대조 45.9670, 최고 joint+verified 47.8884. `구현` (historical source: `generalization_20260908/source/budgeted_evidence.py:71`)
11. **s: 강한 부모 위 근거 추가:** r40는 유지하고, source 질문을 검색키로 추가하면서 원문 부분집합(raw) 또는 해당 출처를 덮는 기존 부모 단위(parent)를 본문으로 사용했다. single/joint/verified와 +2000/+4000을 비교했다. **parent-single+2000 59.2744가 채택**됐다. parent-joint+2000은 59.0149, parent-single+4000은 58.0163. 최종 방법에는 pair 선택과 behavioral verifier를 포함하지 않는다. `구현` (historical source: `generalization_20260908/source/parent_evidence.py:81`)
12. **t: 실제 검색·응답 내부 재귀:** 실패 source 질문에 도움이 되는 키를 추가하고 실제 검색+reader로 다시 평가했다. 최대 3회, 회귀 없는 복구를 우선하며 +4000 상한. 두 변경 채택 후 중단, 최종 dev 59.1275. 내부 두 개선은 별도 dev 후보 수에 더하지 않는다.
13. **v: 다른 질문 표현에서 내부 선택:** 저장 질문 Q0와 표현이 다른 A에서 개선 후보를 선택하고 B는 고정 후 진단했다. 한 변경 후 중단, dev 56.6619. 이는 source 질문 표현의 일반화 점검이며 새 데이터 일반화와 다르다. `t 구현` (historical source: `generalization_20260908/source/run_retrieval_contract.py:54`) · `v 구현` (historical source: `generalization_20260908/source/run_crossview_refinement.py:57`)
14. **w: 동일 메모리 통합:** 본문·출처·세션이 정확히 같은 단위를 합치고, 본문/모든 기존 키/본문과 다른 키만으로 검색했다. 세 부모×세 키 방식, 9개 55.7434–58.6203. 최고도 r40와 동점. `구현` (historical source: `generalization_20260908/source/identity_consolidation.py:13`)
