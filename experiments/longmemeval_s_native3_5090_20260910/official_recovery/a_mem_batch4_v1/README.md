# A-Mem-batch4 v1

This user-authorized variant changes the memory input unit from one turn to at most four consecutive turns. It is named **A-Mem-batch4**, with `VERSION` and `policy.harness_version` equal to `a_mem_batch4_v1`. It is a separate experiment, not the original per-turn A-MEM baseline. Use a fresh `runs/a_mem_batch4_v1` run and a newly verified runtime/source receipt. The current intended host is Ada instance50558368; the parent operator owns serving, scheduling and deployment. This directory performs no service or provider lifecycle operations.

The baseline is sibling `a_mem_paper_v2/runner.py`, SHA256 `1c49096eee2a0ed9b487e15c41cf6fe6496a1858b49b1da5720c06e50c2e559e`. All five archived upstream files are byte-identical, pinned to WujiangXu/A-mem commit `0c8039f28fdcc08189a23c07a3437d9d2482f9c2`. The original class AST, prompts, metadata generation, memory evolution, query rewrite, k10 retrieval, category1 QA, model Qwen3.5-9B, temperature0.7 and1000-token output budget remain unchanged. Handled native fallbacks remain counted native outcomes; transport/unhandled errors remain failures.

For each original session independently, turn ranges are `[0:4]`, `[4:8]`, and so on, including any final1–3 turns. No batch crosses a session boundary or truncates source content. Each note is exactly a newline-join of the original adapter strings `Speaker ` + role + `says : ` + content. `advancedMemAgent.add_memory` invokes the original `AgenticMemorySystem.add_note`; its discarded return value is not interpreted as success. Instead, successful insertion must create exactly one new native memory ID. The existing session date conversion supplies the same native `YYYYMMDDHHMM` timestamp as the baseline. Original session IDs, date strings, role/content and order remain unchanged in label-free `source.json`.

`batch_manifest.json` binds the source hash, session/turn counts, batch size, every session index/ID/date, exact half-open turn ranges, native time, original-turn digest and rendered-note digest. Together with `source.json`, this reconstructs the complete original input even when content contains newlines or speaker-like text; reconstruction never splits the rendered note. Canonical source roles are user/assistant; other roles or extra evaluation annotations are rejected. Empty sessions remain in raw source but create no note.

After each successful native insertion, `batch_calls.jsonl` records that exact manifest row, the added native note ID, logical LLM call range, duration and wall timestamp. `construction_progress.json` records completed batches and original turns. Failed calls never become successful journal rows. Raw native requests/responses, handled fallback evidence and usage/timing remain available in the inherited native artifacts. The physical meter journal is authoritative for SDK retry accounting; the variant uses meter method `a_mem_batch4` and its new protocol digest.

Before worker success, parent finalization, and cache reuse, coverage verification recomputes the manifest from source, checks every batch exactly once and in order, validates contiguous native call ranges, and matches final native memory IDs/content/timestamps. Evolution may alter the original algorithm's metadata/context/tags/links. It must not lose a batch note's original content/time. Source/query/worker/runtime, canonical500 population, current source hashes and new policy are bound to the protocol identity. Boolean values cannot impersonate numeric manifest/progress fields.

Only the parent seals after a real worker subprocess exit0, with console/cache files closed. Completion requires exact artifact inventory, no failure marker, full batch/source coverage, native QA and all mandatory artifacts. Old per-turn seals, changed worker/protocol data, modified caches, missing/duplicate/cross-session batches and additional unsealed files are refused. Unsealed failures are preserved; later attempts reconstruct the complete history under a fresh attempt directory. A process-held nonblocking Linux `flock` prevents a second CLI parent from allocating attempts or writing aggregates in the same run.

The population denominator remains500. A successful IDs-file smoke uses `subset_generation_complete` and `selected_count`; it never claims full completion. A later full invocation may reuse only verified successes under the identical new batch4 protocol. Do not combine old per-turn or other-method results with this variant.
