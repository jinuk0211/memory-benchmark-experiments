# Frozen paper baseline with common date-format compatibility

This is a new sibling of the reviewed `paper_lme_adapter` v1 clone. It adds a generic date metadata parser wrapper so the existing frozen calendar normalizers can interpret numeric timestamps. It does not edit the previous clone, its deployment bundle, or any original experiment. Use a new deployment root such as `/workspace/paper_longmemeval_20260910_date_v2` and a fresh output/cache namespace such as `runs/paper_frozen_lme12_dates_qwen35_minilm_r1`.

The eleven frozen algorithm modules, four recipe plans, Qwen FP16/MiniLM runtime, writer/reader/scorer capacities, native meters, reader, retriever, budgets, cache keys, seeds, sampling, source-QA generation, complete utility scoring, and three arms remain unchanged on disk. Only the copied `run_transfer.py` changes: it installs `date_metadata_adapter.py` after validating frozen source plans and before loading samples, includes that adapter in actual source hashes, and records the adapter's explicit version/profile in the immutable protocol. The two new Python files are the adapter and its focused tests.

The adapter wraps both `continuous.parse_date` and `continuous_v2.parse_date`. This is necessary because r06's `continuous_v2.construct -> anchor_units -> calendar_anchor` resolves the v2 module global, while r40's `memory_ops.fuse_evidence -> continuous.anchor_units` resolves the original continuous module global. Both module paths and both actual caller-global dictionaries are checked before either function is replaced. A foreign project module or conflicting parser fails without partially installing a patch; repeat installation is idempotent.

Original parsing runs first. Its successful object and original exceptions are preserved. Only an original `None` allows strict full-string fallback for `YYYY/MM/DD (ddd) HH:MM`, `YYYY-MM-DD`, or `YYYY-MM-DD HH:MM`. Numeric fields must be valid; the English weekday on slash-format stamps must match the calendar day. Unsupported/malformed fallback formats remain `None`, as before. There are no dataset names, question IDs, target labels, answers, or method IDs in the parser's decisions. This is a common format adapter, available to every stage and arm.

No original source timestamp, question timestamp, conversation/history object, original memory input object, or writer source prompt is rewritten. The existing algorithm's resulting temporal annotations and downstream reader contexts can change because the date is now interpreted correctly. Seed originally has no r06 calendar stage; this wrapper does not inject one. Refined continues to build on its r40 parent. On the synthetic fixture `2023/05/30 (Tue) 23:40`, both real calendar paths now interpret `yesterday` as 29 May 2023 while the original timestamp and inputs remain identical.

One inherited limitation remains explicit: `anchor_units` strips a `(Session date: ...)` prefix using the original non-greedy regex. Numeric timestamps themselves contain weekday parentheses, so derived text can retain a clock suffix after the first closing parenthesis. That regex was not silently changed in this version. The original algorithm also reduces parsed timestamp references to dates in its derived `Recorded on` label; source sessions still preserve their full timestamp. Any further representation change needs a separately documented version and comparison.

The runtime capacity adapter is byte-identical to reviewed v1: `transfer_runtime.py` SHA256 `c3ce1cc184c6a002b94490595b913989e6620fde07d046318cd831004e4c3f22`. Writer context is 65,536 with chunked prefill; reader/scorer are 8,192. Read evidence remains 2,048, answer output 96, extra storage 2,000, and MiniLM native window 256. Qwen revision is `c202236235762e1c871ad0ccb60c8ee5ba337b9a`; MiniLM revision is `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`. Original native cache keys deliberately do not include this metadata adapter; use only fresh outputs/caches and never import prior memories or result items. Protocol hashes include the new adapter and runner and prevent incompatible resumption.

`DATE_METADATA_COVERAGE.json` records a metadata-only scan of the canonical cleaned LongMemEval S file: all 23,867 source timestamps and 500 question timestamps parse under the generic fallback, including weekday consistency, with zero failures. No target question/answer text or previous outcomes were inspected. This checks metadata coverage and does not measure model performance. Both parser functions were also compared on all 288 canonical LoCoMo source timestamps: every original parse succeeded and all results remained identical after installing the wrapper. The frozen reader still receives the original question-date string; no new question-time reasoning stage was introduced.
